# V.A.L.I.D Backend API

This backend provides authentication, user management, and inspection processing APIs for the V.A.L.I.D product compliance workflow.

## Base URL

- Local development: http://localhost:3000

## Python OCR Service

Inspection scans use the Python FastAPI microservice described in the OCR/compliance README. Configure its base URL before starting this backend:

```env
PYTHON_SERVICE_URL=https://validaibackend-production-1904.up.railway.app
USE_MOCK_INSPECTION_SERVICE=false
```

The Python API documentation is available at [Railway Swagger docs](https://validaibackend-production-1904.up.railway.app/docs). `POST /inspections/scan` uploads the `front`, `back`, and `side` images to the Python `/extract-product` endpoint, then sends the extracted fields and OCR boxes as JSON to `/analyze-compliance`. Use the service host as `PYTHON_SERVICE_URL`; do not append `/docs`. Set `USE_MOCK_INSPECTION_SERVICE=true` only for local testing without Python.

## Authentication

Most inspection endpoints require a Bearer token.

Header format:

```http
Authorization: Bearer <jwt_token>
```

The token is generated by the login endpoint and includes the authenticated `userId`.

## 2) User Routes

Base path: `/user`

### POST /user/create

Creates a new user.

#### Request format

- `multipart/form-data` if uploading profile image
- `application/json` if no image is uploaded

#### Fields

- `officerId` (required): string
- `name` (required): string
- `email` (required): string
- `password` (required): string
- `phone` (optional): string
- `profileImage` (optional): image file

#### Example request

```bash
curl -X POST http://localhost:3000/user/create \
  -F "officerId=OFF_4021" \
  -F "name=Rohit Sharma" \
  -F "email=rohit@example.com" \
  -F "password=securePass123" \
  -F "phone=9876543210" \
  -F "profileImage=@avatar.jpg"
```

#### Example success response

```json
{
  "success": true,
  "message": "User created successfully",
  "data": {
    "_id": "64fe2f7d9a1d4d5f8a7c1234",
    "officerId": "OFF_4021",
    "name": "Rohit Sharma",
    "email": "rohit@example.com",
    "phone": "9876543210",
    "avatarUrl": "https://res.cloudinary.com/.../avatar.jpg",
    "createdAt": "2026-08-29T12:00:00.000Z",
    "updatedAt": "2026-08-29T12:00:00.000Z"
  }
}
```

#### Error response

```json
{
  "success": false,
  "message": "Email already exists"
}
```

Required.

`multipart/form-data`

- `side`: image file

## Status Values

Inspection status values:

- `PROCESSING`
- `COMPLIANT`
- `NON-COMPLIANT`
- `REVIEW`

Overlay types:

- `VALID`
- `VIOLATION`
- `REVIEW`

Common violation code:

- `MRP_UNCLEAR`

---

## Notes

- The backend uses JWT-based authentication.
- Inspection upload endpoints require three image files: `front`, `back`, and `side`.
- The raw OCR output is stored under `extracted_fields` and `raw_ocr_boxes`.
- Merged OCR fields are returned under `merged_fields`; image-specific OCR data is returned under each image's `extracted_fields` and `raw_ocr_boxes`.
- Overlay bounding boxes use normalized coordinates in the format `[x_min, y_min, x_max, y_max]`, with values from `0` to `1`.
- When a field is not found in OCR, it may be stored as `null` or empty values depending on the source payload.

For implementation details, see the route files and controller files in the `src` folder.
